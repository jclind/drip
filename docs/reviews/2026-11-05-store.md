# Store review, 2026-11-05

A Chrome Web Store reviewer's pass over drip at `be8ab2b` (main), the day before it's due to be submitted. Review only: no code, config, or tests changed.

Three read-only agents split the work: the manifest and what `bin/build-release` ships, data use against `store/PRIVACY.md`, and the listing copy, single purpose, and trademark. One agent ran `bin/build-release` in a scratch copy, packed the zip with Chrome for Testing 153, and loaded it. I then read the code behind every finding and marked each one confirmed, plausible, or rejected. Two agents cited line numbers in `store/LISTING.md` and `store/PRIVACY.md` that don't exist. The line numbers below are corrected.

Known items aren't repeated: the missing public privacy URL, the 1.0.0 version bump, and the visual assets "coming with the design work" are all in `store/LISTING.md` already. They come up again only where they change what blocks tomorrow.

I couldn't check current policy text from this session, because developer.chrome.com is blocked by the network settings. Where a finding depends on policy I'm unsure of, it says so.

## Summary

Nothing in the code looks likely to get drip rejected. The risks are in the paperwork: the listing claims "No host permissions" while the manifest has one, the privacy policy misses five weeks of features, and the store summary doesn't mention YouTube. All of these are text fixes, plus one line in `manifest.json`.

Blocks tomorrow: findings 1 to 5. Finding 1 is partly known. Finding 6 is worth doing if there's time.

### 2. "No host permissions" is false, and nothing justifies the background fetch. Blocks.

- Where: `store/LISTING.md:19` says "No host permissions". `manifest.json:8` declares `"host_permissions": ["https://www.youtube.com/*"]`, added on 2026-11-04 in `14e36fc`.
- What uses it: `lookUpChannel` at `src/background.js:328`. It fetches `https://www.youtube.com/@handle` from the service worker, without cookies, after Settings adds a channel by handle. DESIGN.md:475 records that this needs the permission.
- What Chrome grants: in the packed build, Chrome lists www.youtube.com, m.youtube.com, and www.youtube-nocookie.com as granted hosts. The last two come from the content-script matches.
- Trigger: a reviewer compares the justification text with the manifest and the install prompt.
- Impact: a written claim that contradicts the package, in front of the person deciding. The justification field also has nothing to say about the worker's fetch.
- Fix: delete the sentence, and add a host justification along these lines: "www.youtube.com: content scripts that change the page, and a cookie-less fetch of a channel's public page to show its name and picture after you add it in Settings." Two notes still assume no host permission, `src/popup/popup.js:71-73` and DESIGN.md:317. They're stale but don't affect the store.
- Unsure: I'm fairly sure the dashboard has its own host-permission justification field and won't submit with it empty. I can't say whether a wrong justification alone gets an extension rejected.

### 3. The store summary is the manifest description, and it doesn't say YouTube. Blocks.

### 4. The privacy policy is out of date. Blocks, because it gets published tomorrow.

- Stored but not listed. The list is at `:7-11`.

  - The id and title of each video unlocked with "I need this one", stored next to the typed reason (`state.js:627`). The policy mentions only the reason.
  - `allowedToday`, `unlocked`, and `installedAt`.
  - The multi-tab clock in `chrome.storage.session` (`background.js:160`, `:180`). Line 5 says `chrome.storage.local` only. The clock holds timestamps and random keys, no video ids.
- Network loads not described. Line 15 says "drip talks only to YouTube".
  - The worker's fetch of `https://www.youtube.com/@handle` (`background.js:328`).
  - A hidden frame of the home page `/`, signed in, that scrolls for more videos once the visible grid is all revealed (`src/content/home.js:206`, frame at `:168-196`). Only the Subscriptions frame is mentioned.

- Trigger: a reviewer or user compares the policy with the extension's behavior, for example by adding a channel in Settings and watching the network.

- Fix:

  - Name the hosts: "YouTube and its image servers: i.ytimg.com, yt3.ggpht.com, yt3.googleusercontent.com".
  - Describe both hidden frames and the cookie-less channel fetch.
  - List the three YouTube hosts.

### 5. The single-purpose statement only fits Full drip. Blocks, as a dashboard text fix.

- Trigger: a reviewer picks Quiet on the welcome page and finds no allowance anywhere.

### 6. The store build tries to load a file it deleted. Fix if there's time.

- Where: `src/background.js:4-9` calls `importScripts('devpanel/clock.js')` inside try/catch. `bin/build-release` deletes `src/devpanel`.
- Trigger: the agent loaded the packed build with developer mode on. Each service-worker start logged "An unknown error occurred when fetching the script" on `chrome://extensions`. A copy with those six lines removed logged nothing. I read the code, but I didn't rerun Chrome myself.
- Impact: a reviewer who loads the package sees a red Errors button, and the shipped worker names a file that isn't in the zip. Behavior is fine, since the catch falls back to real time.
- Fix: have `bin/build-release` cut the block from `src/background.js` in the build copy, the way it already rewrites the manifest. Another way: load the dev clock only when the manifest has the devpanel content scripts, which is the test `shipsPanel` uses at `background.js:395`.

### 7. The listing doesn't say what drip changes on YouTube. Low; goes in the description from finding 1.

None of these are in `store/LISTING.md`:

- A welcome tab opens on install (`background.js:259-265`).
- m.youtube.com and directly opened youtube-nocookie pages redirect to the desktop site (`redirect.js`).
- Comments sit behind a button.
- Videos pause at the lock, at the start of Dry hours, and when the miniplayer opens.
- The sidebar becomes drip's menu.
- Quiet moves YouTube's search box.
- Shorts open as regular videos.
- Autoplay gets switched off and theater mode on (`src/content/watch.js:94-146`).

The welcome tour covers most of this, apart from theater mode. Each item is small. Together they're the kind of thing a reviewer counts as undisclosed behavior. Fix: a short "What drip changes on YouTube" list in the detailed description.

### 8. drip hides some YouTube ads and doesn't say so. Medium; disclosure isn't a blocker.

- Where: `src/content/early.css:156-157` hides `ytd-search-pyv-renderer` and `ytd-ad-slot-renderer` in search. Hiding the watch page's right column at `early.css:44-47`, and the home grid, takes the display ads there with it.
- What it doesn't do: nothing skips, mutes, or blocks video ads. Q27 holds: an ad isn't charged, and the pill says so.
- Trigger: a search with a promoted result.
- Impact: I know of no store policy against hiding page ads, since ad blockers are listed in the store. It's still behavior the listing should mention, and YouTube's anti-adblock checks might notice the hidden slots, which is unverified.
- Fix: add a line to the description, such as "Hides the ads in search results and beside videos. Video ads play as usual." Or decide to stop hiding the search ad slots. That's open question 2.

### 9. The broken-page report sends the full user agent. Low.

`src/content/common.js:220` puts `navigator.userAgent` in the report, which includes the operating system. `store/PRIVACY.md:17` says "your browser version". "Page path" checks out: only `location.pathname` goes in, and the only paths reported are `/`, `/watch`, and `/results`. Fix: say "your browser and operating system version".

### 10. "Removing drip deletes everything it stored" has two exceptions. Low.

- `sessionStorage['drip-kept']` on youtube.com (`watch.js:821`) lasts until the tab closes. It's a single number.
- Export files stay in Downloads (`options.js:1070-1078`). They hold titles, typed reasons, 90 days of history, and the channel lists (`state.js:1239-1244`).

Fix: add "except files you exported yourself" to `store/PRIVACY.md:19`.

### 11. No "not affiliated" line, and drip's menu calls itself YouTube. Low.

- No YouTube logo, red play button, or "YouTube" in the name. The icons are a blue drop. "YouTube" in the copy is descriptive.
- Nothing anywhere says drip isn't affiliated with YouTube. As far as I know store policy doesn't require it, but YouTube's brand guidelines expect it, and it costs one sentence.
- `src/content/menu.js:59` gives drip's own nav `aria-label: 'YouTube'`, so screen readers announce drip's menu as YouTube's. It's an accessibility issue, not a store one.
- Fix: add "drip isn't affiliated with or endorsed by YouTube or Google." to the description, and label the nav "drip menu" in a later release.

### 12. Dev-only code still ships, but nothing can reach it. Low.

- The localhost route: `background.js:268-300`, the `onMessageExternal` listener and its reload, tick, and settings handlers.
- The dev clock and developer-mode handlers: `background.js:340-404`, `Drip.devAction` at `state.js:1106`, and the options page's `createElement('script')` for `../devpanel/profiles.js` (`options.js:1241`).
- Why it can't run: in the build, `externally_connectable` is gone, the listener drops any sender whose origin isn't localhost, `devEnabled` is false, and `shipsPanel` is false. The agent confirmed at runtime that the dev messages answer `dev-off` and the options page's dev section stays hidden.
- Impact: none at runtime. A reviewer's grep finds a script element and an external-message listener, and has to read on to see they're inert.
- Fix: none needed tomorrow. Optionally strip it in the build later, or add a sentence to the notes for the reviewer.

## Plausible

### 13. The hidden frames may load ads that nobody sees. Medium; unsure.

- Where: `src/content/home.js:168-196` loads `/feed/subscriptions` or `/` in a frame at opacity 0 and scrolls it by script.
- Why ads would render: no drip content script runs in frames (none set `all_frames`), so `early.css` doesn't apply there. YouTube's own feed renders in full, ad slots included.
- Trigger: in Curated, reveal until the visible grid runs out, and the frame of `/` loads and scrolls.
- Impact: if YouTube's ad slots load in the frame, that's ad impressions with no viewer. I can't cite the policy text, but Google treats invisible impressions as abuse. I didn't confirm that ads load in the frame.
- Check: watch the Network tab for ad requests during a reveal that reads a frame.
- Fix, if they do load: hide ad renderers in the frame's document once it loads, or block them before the frame paints.

### 14. A reviewer may stop at the hidden frames themselves. Low; unsure.

Same code as finding 13. It's same-origin, signed in as the user, and described in PRIVACY.md for Subscriptions, though not for the home page (finding 4). Hidden frames sometimes get a closer look. One sentence in the notes for the reviewer covers it.

### 15. Autoplay off and theater mode on outlast an uninstall. Low.

`watch.js:94-146` clicks YouTube's own toggles, and YouTube remembers them the way it would remember the user's own click. That's Q26 and Q2, so it's by design. A user who uninstalls finds theater mode still on and autoplay still off. I believe YouTube stores both in a cookie or the account, but I didn't verify that. It belongs in finding 7's list.

## Rejected

- Other extensions can message the worker, because the build has no `externally_connectable`. Rejected: they can, but `background.js:278` drops any sender whose origin isn't localhost, and a store build never turns on the dev route.
- `chrome.tabs` use needs the `tabs` permission. Rejected: shipping code reads only `id`, `windowId`, and `lastAccessed`, never `url` or `title`. `tabs.query`, `tabs.update`, `windows.*`, `action.setIcon`, and `runtime.getContexts` need no permission.
- Remote code. Rejected: no `eval`, `new Function`, string timers, `import()`, or remote scripts or CSS. `innerHTML` only takes static literals. The fetched channel HTML is only parsed with regexes (`state.js:1611`), never inserted or run. The one dynamic `<script>` is the local `../devpanel/profiles.js`, which the build deletes and which fails quietly.
- drip changes other sites through embeds. Rejected: no `all_frames`, and `redirect.js:9` returns early inside a frame.
- "One recommendation at a time" is false in Curated's unlimited mode. Rejected: unlimited cards are free, but there's still one card up at a time. The summary is still wrong for Quiet, which is finding 3.
- The zip carries stray files. Rejected: 81 files, only `manifest.json`, `src/`, and `icons/`. No tests, `dev/`, markdown, plist, demos, or dotfiles, and the code isn't minified.
- `minimum_chrome_version` 121 is too low. Rejected: the newest features found are `tabs.Tab.lastAccessed` at 121 and `runtime.getContexts` at 116.
- The 128px icon's artwork is 78×108 instead of the suggested 96×96. Not a finding: that's Google's design guideline, not a validator check.
- Save hides in other languages (`early.css:61`). Out of scope: the code comment already records it, and audit finding 8 is the same class.
